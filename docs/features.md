### F01 容器管理

| 项目 | 内容 |
|------|------|
| 功能ID | F01 |
| 功能名称 | 容器管理 |
| 功能描述 | 提供容器的完整生命周期管理，包括创建、启动、停止、删除、克隆、导入、导出。每个容器拥有独立的 rootfs、Wine prefix 和 container.yml 配置文件，实现容器间的完全隔离。 |

**输入/输出**

| 操作 | 输入 | 输出 |
|------|------|------|
| create | 容器名称、模板ID（可选）、配置参数 | 创建完成的容器实例，返回容器ID |
| start | 容器ID/名称 | 运行中的容器进程，Wine prefix 已初始化 |
| stop | 容器ID/名称 | 容器进程终止，状态保存 |
| delete | 容器ID/名称、确认标志 | 容器资源完全清除 |
| clone | 源容器ID/名称、新容器名称 | 与源容器一致的新容器实例 |
| import | 导出文件路径、目标容器名称 | 还原的容器实例 |
| export | 容器ID/名称、输出路径 | 打包的容器归档文件 |

**前置条件**

- PRE-F01-01：Termux 环境已正确安装并授予必要权限（存储访问等）
- PRE-F01-02：Box86/Box64 及 Wine 组件已安装
- PRE-F01-03：容器存储目录可写且磁盘空间充足
- PRE-F01-04：容器名称符合命名规范（字母/数字/连字符，3-32字符）

**后置条件**

- POST-F01-01：容器状态在容器列表中可查询
- POST-F01-02：容器目录结构完整（rootfs/、prefix/、container.yml）
- POST-F01-03：容器配置持久化到 container.yml
- POST-F01-04：容器运行时资源使用可监控

**正常流程 — 创建容器**

1. 用户执行 `grapevine create --name <名称>` 或指定模板 `--template <模板ID>`
2. 系统验证容器名称唯一性
3. 系统创建容器目录结构：`<storage>/containers/<名称>/`
4. 系统初始化 rootfs（基于最小根文件系统或模板 rootfs）
5. 系统初始化 Wine prefix（执行 wineboot）
6. 系统生成 container.yml 默认配置
7. 系统注册容器到容器索引
8. 返回容器创建成功信息及容器ID

**正常流程 — 启动容器**

1. 用户执行 `grapevine start <容器名称>`
2. 系统检查容器当前状态（已停止方可启动）
3. 系统加载 container.yml 配置
4. 系统配置环境变量（Box86/Box64 库路径、Wine 路径等）
5. 系统挂载存储映射目录
6. 系统配置网络模式
7. 系统启动图形子系统（根据配置选择 GPU 驱动）
8. 系统启动音频子系统
9. 系统启动 Wine 实例（wineboot → 运行状态）
10. 容器状态更新为 running

**正常流程 — 停止容器**

1. 用户执行 `grapevine stop <容器名称>`
2. 系统检查容器当前状态（运行中方可停止）
3. 系统向 Wine 进程发送终止信号
4. 系统等待进程优雅退出（超时阈值 30 秒）
5. 若超时未退出，强制终止进程
6. 系统卸载存储映射
7. 系统释放图形/音频资源
8. 容器状态更新为 stopped

**正常流程 — 删除容器**

1. 用户执行 `grapevine delete <容器名称>` 或 `--force` 跳过确认
2. 系统检查容器状态（运行中的容器需先停止）
3. 系统提示用户确认删除操作
4. 用户确认
5. 系统递归删除容器目录（rootfs、prefix、配置）
6. 系统从容器索引中移除记录
7. 系统清理关联的快照数据
8. 返回删除成功信息

**正常流程 — 克隆容器**

1. 用户执行 `grapevine clone <源容器> --name <新名称>`
2. 系统验证源容器存在且新名称唯一
3. 系统创建新容器目录
4. 系统复制 rootfs（使用 reflink 或硬链接优化空间）
5. 系统复制 Wine prefix
6. 系统复制并修改 container.yml（更新容器名称和ID）
7. 系统注册新容器到索引
8. 返回克隆成功信息

**正常流程 — 导出容器**

1. 用户执行 `grapevine export <容器名称> --output <路径>`
2. 系统检查容器存在性
3. 系统暂停容器（若运行中）
4. 系统将容器目录打包为 tar.gz 归档
5. 归档包含：rootfs、prefix、container.yml、元数据
6. 系统恢复容器运行状态（若之前为运行中）
7. 返回导出文件路径

**正常流程 — 导入容器**

1. 用户执行 `grapevine import <归档文件> --name <名称>`
2. 系统验证归档文件完整性（校验哈希）
3. 系统验证名称唯一性
4. 系统创建容器目录
5. 系统解压归档到容器目录
6. 系统更新 container.yml 中的容器ID和名称
7. 系统注册容器到索引
8. 返回导入成功信息

**异常流程**

| 异常编号 | 触发条件 | 处理方式 |
|---------|---------|---------|
| EX-F01-01 | 容器名称已存在 | 返回错误提示，建议使用其他名称 |
| EX-F01-02 | 磁盘空间不足 | 返回错误提示，显示所需空间与可用空间 |
| EX-F01-03 | Wine 初始化失败 | 回滚已创建的目录，返回错误日志 |
| EX-F01-04 | 容器运行中无法删除 | 提示用户先停止容器或使用 --force |
| EX-F01-05 | 导出文件损坏 | 校验失败，拒绝导入并提示文件不完整 |
| EX-F01-06 | 启动时依赖组件缺失 | 返回缺失组件列表，提示安装 |
| EX-F01-07 | 进程优雅退出超时 | 强制终止并记录警告日志 |
| EX-F01-08 | rootfs 初始化中断 | 清理已创建的部分目录，回滚操作 |

**业务规则**

- BR-F01-01：每个容器名称在全局范围内唯一
- BR-F01-02：容器ID为 UUID v4 格式，自动生成
- BR-F01-03：容器目录结构固定为 `{rootfs, prefix, container.yml, snapshots/}`
- BR-F01-04：运行中的容器不可删除，必须先停止
- BR-F01-05：克隆操作不复制快照数据
- BR-F01-06：导出归档格式为 `.gv.tar.gz`，包含校验文件 `manifest.sha256`
- BR-F01-07：同一时刻同一容器只能有一个运行实例

**依赖关系**

- 依赖 F03 模板系统（创建时可选择模板）
- 依赖 F04 图形子系统（启动时初始化图形驱动）
- 依赖 F05 音频子系统（启动时初始化音频后端）
- 依赖 F07 存储映射（启动时挂载共享目录）
- 依赖 F08 网络支持（启动时配置网络模式）
- 依赖 F09 组件管理（依赖已安装的 Box86/Box64/Wine 组件）
- 依赖 F12 声明式配置（读取 container.yml）

### F02 快照系统

| 项目 | 内容 |
|------|------|
| 功能ID | F02 |
| 功能名称 | 快照系统 |
| 功能描述 | 提供容器状态的快照创建、列表查询、回滚和删除功能，采用增量存储策略，仅保存与上一快照的差异数据，节省存储空间。 |

**输入/输出**

| 操作 | 输入 | 输出 |
|------|------|------|
| create | 容器ID/名称、快照名称（可选）、描述（可选） | 快照ID、创建时间、占用空间 |
| list | 容器ID/名称 | 快照列表（ID、名称、时间、大小、描述） |
| rollback | 容器ID/名称、快照ID/名称 | 容器状态回滚至快照点 |
| delete | 容器ID/名称、快照ID/名称 | 快照数据删除，空间释放 |

**前置条件**

- PRE-F02-01：目标容器已创建
- PRE-F02-02：创建快照时容器应为停止状态（确保数据一致性）
- PRE-F02-03：回滚操作前容器必须停止

**后置条件**

- POST-F02-01：快照元数据记录到容器快照索引
- POST-F02-02：增量数据持久化存储
- POST-F02-03：回滚后容器状态与快照点一致

**正常流程 — 创建快照**

1. 用户执行 `grapevine snapshot create <容器名称> --name <快照名称>`
2. 系统检查容器状态（建议停止状态，运行中创建给出警告）
3. 系统扫描容器 rootfs 和 prefix 目录
4. 系统计算与上一快照的差异（新增/修改/删除的文件）
5. 系统将差异文件以增量方式存储到 `snapshots/<快照ID>/`
6. 系统生成快照元数据（时间戳、文件列表、校验和、父快照引用）
7. 系统注册快照到容器快照索引
8. 返回快照创建成功信息

**正常流程 — 查询快照列表**

1. 用户执行 `grapevine snapshot list <容器名称>`
2. 系统读取容器快照索引
3. 系统按时间倒序排列快照
4. 输出快照列表（ID、名称、创建时间、增量大小、累计大小、描述）

**正常流程 — 回滚快照**

1. 用户执行 `grapevine snapshot rollback <容器名称> --snapshot <快照ID>`
2. 系统检查容器状态（必须为停止状态）
3. 系统验证目标快照存在
4. 系统提示用户确认（回滚将丢失快照后的数据变更）
5. 用户确认
6. 系统根据快照链重建容器 rootfs 和 prefix
7. 系统更新 container.yml 配置（如快照时配置不同）
8. 容器状态更新为 stopped（回滚完成）
9. 返回回滚成功信息

**正常流程 — 删除快照**

1. 用户执行 `grapevine snapshot delete <容器名称> --snapshot <快照ID>`
2. 系统验证快照存在
3. 若快照为中间节点（有子快照），系统合并增量数据到子快照
4. 若快照为叶子节点，直接删除增量数据
5. 系统更新快照索引链
6. 返回删除成功信息

**异常流程**

| 异常编号 | 触发条件 | 处理方式 |
|---------|---------|---------|
| EX-F02-01 | 容器运行中创建快照 | 发出警告，允许继续但提示数据可能不一致 |
| EX-F02-02 | 容器运行中尝试回滚 | 拒绝操作，提示先停止容器 |
| EX-F02-03 | 快照不存在 | 返回 404 错误 |
| EX-F02-04 | 磁盘空间不足无法创建快照 | 返回错误，显示所需空间 |
| EX-F02-05 | 快照链损坏 | 提示损坏位置，建议从更早快照回滚 |
| EX-F02-06 | 回滚过程中 I/O 错误 | 中止回滚，保持容器原状态不变 |

**业务规则**

- BR-F02-01：快照采用增量存储，首个快照为全量快照
- BR-F02-02：快照链为线性链表结构，每个快照引用其父快照
- BR-F02-03：删除中间快照时，其增量数据合并至子快照，确保链完整性
- BR-F02-04：每个容器最大快照数量限制为 20（可配置）
- BR-F02-05：快照名称在同一容器内唯一
- BR-F02-06：运行中容器创建快照标记为"不一致快照"

**依赖关系**

- 依赖 F01 容器管理（快照绑定于容器）
- 依赖 F12 声明式配置（回滚时恢复配置）

### F03 模板系统

| 项目 | 内容 |
|------|------|
| 功能ID | F03 |
| 功能名称 | 模板系统 |
| 功能描述 | 提供预配置的容器模板，快速创建针对特定用途优化的容器。包含 6 个内置模板和自定义模板导出功能。 |

**输入/输出**

| 操作 | 输入 | 输出 |
|------|------|------|
| list | 无 | 模板列表（ID、名称、描述、用途） |
| show | 模板ID | 模板详细配置信息 |
| export | 容器ID/名称、模板名称、描述 | 自定义模板文件 |
| import | 模板文件路径 | 注册到模板库 |

**内置模板定义**

| 模板ID | 名称 | 用途 | 预装组件 | 配置特点 |
|--------|------|------|---------|---------|
| gaming-dx11 | DX11 游戏模板 | DirectX 11 游戏 | DXVK、Turnip/Zink、PulseAudio | 优化帧率，禁用 compositor，大页面内存 |
| gaming-dx9 | DX9 游戏模板 | DirectX 9 老游戏 | D8VK、Turnip/VirGL、PulseAudio | 兼容旧游戏，软件渲染回退 |
| gaming-dx12 | DX12 游戏模板 | DirectX 12 游戏 | VKD3D、Turnip/Zink、PulseAudio | 异步计算优化，光线追踪支持 |
| office | 办公模板 | Office 类应用 | Wine staging、PulseAudio、ALSA | 稳定优先，字体渲染优化 |
| development | 开发模板 | 开发工具 | Wine staging、完整开发库 | 调试符号，详细日志 |
| minimal | 最小模板 | 自定义基础 | Wine 最小安装 | 无预装，最小占用 |

**前置条件**

- PRE-F03-01：模板所需的组件已安装（或创建时自动安装）
- PRE-F03-02：导出模板时源容器存在

**后置条件**

- POST-F03-01：基于模板创建的容器继承模板的全部配置
- POST-F03-02：自定义模板注册后可在模板列表中查询

**正常流程 — 从模板创建容器**

1. 用户执行 `grapevine create --name <名称> --template gaming-dx11`
2. 系统查找模板定义
3. 系统检查模板所需组件是否已安装
4. 若组件缺失，提示用户安装或自动安装（取决于配置）
5. 系统创建容器目录结构
6. 系统根据模板配置初始化 rootfs
7. 系统根据模板配置初始化 Wine prefix（安装预装组件）
8. 系统根据模板生成 container.yml（图形驱动、音频后端、环境变量等）
9. 系统注册容器到索引
10. 返回创建成功信息

**正常流程 — 导出自定义模板**

1. 用户执行 `grapevine template export <容器名称> --name <模板名称> --desc <描述>`
2. 系统读取容器配置和已安装组件信息
3. 系统生成模板定义文件（包含配置、组件列表、描述）
4. 系统将模板文件保存到模板目录
5. 系统注册自定义模板到模板索引
6. 返回导出成功信息

**异常流程**

| 异常编号 | 触发条件 | 处理方式 |
|---------|---------|---------|
| EX-F03-01 | 模板ID不存在 | 返回错误，列出可用模板 |
| EX-F03-02 | 模板所需组件未安装 | 提示安装缺失组件或自动安装 |
| EX-F03-03 | 自定义模板名称与内置模板冲突 | 拒绝导出，建议使用其他名称 |
| EX-F03-04 | 源容器配置不完整 | 提示缺失项，建议修正后导出 |

**业务规则**

- BR-F03-01：内置模板不可修改和删除
- BR-F03-02：自定义模板名称以 `custom-` 前缀标识
- BR-F03-03：基于模板创建的容器可自由修改配置，不影响模板
- BR-F03-04：模板版本与组件版本绑定，组件升级后模板标记为"需更新"

**依赖关系**

- 依赖 F01 容器管理（模板用于创建容器）
- 依赖 F09 组件管理（模板引用组件版本）

### F04 图形子系统

| 项目 | 内容 |
|------|------|
| 功能ID | F04 |
| 功能名称 | 图形子系统 |
| 功能描述 | 管理 Windows 应用的图形渲染管线，提供 Turnip/VirGL/Zink 三种 GPU 驱动的自动选择与手动切换，以及 DXVK/VKD3D/D8VK 的版本管理与安装。 |

**输入/输出**

| 操作 | 输入 | 输出 |
|------|------|------|
| 驱动选择 | GPU 驱动类型、容器ID | 配置更新的容器 |
| DXVK管理 | 版本号、操作（install/list/remove） | 安装/移除的 DXVK 版本 |
| VKD3D管理 | 版本号、操作 | 安装/移除的 VKD3D 版本 |
| D8VK管理 | 版本号、操作 | 安装/移除的 D8VK 版本 |
| 自动检测 | 无 | 推荐的驱动和配置 |

**GPU 驱动选择策略**

| 驱动 | 适用场景 | Vulkan 支持 | OpenGL 支持 | 性能 |
|------|---------|------------|------------|------|
| Turnip | Adreno GPU 设备 | 原生 Vulkan | 不支持 | 最高 |
| VirGL | 需要 OpenGL 的旧应用 | 不支持 | 虚拟 OpenGL | 中等 |
| Zink | 需要 OpenGL + Vulkan 的应用 | 通过 Vulkan | OpenGL→Vulkan | 中高 |

**前置条件**

- PRE-F04-01：设备 GPU 型号已知
- PRE-F04-02：对应 GPU 驱动已安装
- PRE-F04-03：DXVK/VKD3D/D8VK 依赖 Vulkan 运行时

**后置条件**

- POST-F04-01：图形驱动配置写入 container.yml
- POST-F04-02：Wine prefix 中 DLL 覆盖已配置
- POST-F04-03：环境变量已设置（VK_ICD_FILENAMES、MESA_VK_WSI_PRESENT_MODE 等）

**正常流程 — 自动选择图形驱动**

1. 系统检测设备 GPU 型号（通过 /sys/class/kgsl-3d0 或 ro.hardware 属性）
2. 若检测到 Adreno GPU，优先推荐 Turnip
3. 若检测到 Mali/其他 GPU，推荐 Zink（若 Vulkan 可用）或 VirGL
4. 系统检测 Vulkan 支持（vulkaninfo）
5. 系统根据检测结果生成推荐配置
6. 用户确认或手动调整
7. 系统写入配置到 container.yml

**正常流程 — 安装 DXVK 版本**

1. 用户执行 `grapevine component install dxvk --version 2.3`
2. 系统下载 DXVK 2.3 发布包
3. 系统校验发布包 SHA256
4. 系统解压到组件存储目录
5. 系统注册版本到组件索引
6. 返回安装成功信息

**正常流程 — 容器切换图形驱动**

1. 用户执行 `grapevine config <容器名称> --graphics-driver turnip`
2. 系统检查容器状态（建议停止状态）
3. 系统验证目标驱动已安装
4. 系统更新 container.yml 中的 graphics.driver 字段
5. 系统更新 Wine prefix 中的 DLL 覆盖
6. 系统更新环境变量配置
7. 提示用户重启容器以生效

**异常流程**

| 异常编号 | 触发条件 | 处理方式 |
|---------|---------|---------|
| EX-F04-01 | GPU 不支持 Vulkan 但选择了 Turnip/Zink | 返回错误，推荐 VirGL |
| EX-F04-02 | DXVK 安装包下载失败 | 重试 3 次，失败后提示网络问题 |
| EX-F04-03 | DXVK 校验失败 | 删除已下载文件，提示可能被篡改 |
| EX-F04-04 | Vulkan 运行时不可用 | 提示安装 Mesa Vulkan 运行时 |
| EX-F04-05 | 图形渲染崩溃 | 自动回退到软件渲染，记录崩溃日志 |

**业务规则**

- BR-F04-01：Turnip 仅支持 Adreno GPU，其他 GPU 强制使用 VirGL 或 Zink
- BR-F04-02：DXVK/VKD3D/D8VK 可多版本共存，每个容器选择一个活跃版本
- BR-F04-03：驱动切换需重启容器生效
- BR-F04-04：自动检测在首次创建容器时执行，后续可手动覆盖

**依赖关系**

- 依赖 F01 容器管理（图形配置绑定容器）
- 依赖 F09 组件管理（DXVK/VKD3D/D8VK 版本管理）
- 依赖 F12 声明式配置（配置持久化）

### F12 声明式配置

| 项目 | 内容 |

| 功能ID | F12 |

**配置层级**

```
全局配置 (~/.grapevine/config.yml)
```

**全局配置结构**

```yaml
version: "1.0"
storage:

  containers_dir: ~/.grapevine/containers

  templates_dir: ~/.grapevine/templates

defaults:
  template: minimal
  graphics_driver: auto
  audio_backend: pulse
  network_mode: host

components:
  wine:
    active_version: "9.0"
  box64:
    active_version: "0.2.8"
  box86:
    active_version: "0.8.8"

logging:
  level: info
  file: ~/.grapevine/grapevine.log
```

**容器配置结构**

```yaml
version: "1.0"
container:
  id: "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
  name: "my-game"
  created: "2026-05-06T10:00:00Z"
  template: "gaming-dx11"

runtime:
  wine_version: "9.0"
  box64_version: "0.2.8"
  box86_version: "0.8.8"

graphics:
  driver: turnip
  dxvk_version: "2.3"
  vkd3d_version: "2.12"
  d8vk_version: null
  mangohud: true
  vkbasalt: false

audio:
  backend: pulse
  volume: 100

input:
  mode: input-bridge
  gamepad: true
  keymap: null

storage:
  mappings:
    - host: /sdcard/Games
      guest: "D:"
      mode: rw
    - host: /sdcard/Documents
      guest: "E:"
      mode: ro

network:
  mode: host

environment:
  WINEDEBUG: "-all"
  DXVK_HUD: "fps"
  MESA_VK_WSI_PRESENT_MODE: "fifo"
```

**前置条件**

- PRE-F12-01：YAML 解析库可用
- PRE-F12-02：配置文件格式符合 schema 定义

**后置条件**

- POST-F12-01：配置变更持久化到对应 YAML 文件
- POST-F12-02：配置加载时验证 schema 合法性

**正常流程 — 修改容器配置**

1. 用户执行 `grapevine config set <容器名称> graphics.driver virgl` 或直接编辑 container.yml
2. 系统读取当前配置
3. 系统应用变更

6. 若验证失败，回滚变更并提示错误

**异常流程**

| 异常编号 | 触发条件 | 处理方式 |
|---------|---------|---------|
| EX-F12-01 | YAML 语法错误 | 返回解析错误位置和原因 |
| EX-F12-02 | 配置值越界 | 返回合法值范围 |

**业务规则**

- BR-F12-01：容器配置优先级高于全局配置
- BR-F12-02：命令行参数优先级高于配置文件

## 6. 用户工作流

### 6.1 首次安装初始化工作流

```
用户安装 Termux → 安装 Grapevine → 初始化环境 → 安装核心组件 → 完成
```

**详细步骤：**

1. 用户在 Android 设备上安装 Termux
2. 用户在 Termux 中执行 `pkg install grapevine` 或从源码构建
3. 用户执行 `grapevine init`
4. 系统检测设备信息（CPU 架构、GPU 型号、Android 版本、可用存储）
5. 系统创建目录结构（`~/.grapevine/` 及子目录）
6. 系统生成全局配置文件 `config.yml`
7. 系统提示安装核心组件（wine、box64、box86）
8. 用户确认安装
9. 系统下载并安装核心组件
10. 系统执行 `grapevine doctor` 自动诊断
11. 系统报告环境状态（组件版本、GPU 驱动、权限状态）
12. 若存在问题，系统给出修复建议
13. 初始化完成，用户可开始创建容器

**异常处理：**

- 设备架构不支持（非 ARM64）：提示设备不兼容
- 存储权限未授予：引导用户到系统设置授权
- 网络不可用：提示离线模式（需手动提供组件包）
- 磁盘空间不足：提示所需最小空间（约 2GB）

---

### 6.2 从模板创建游戏容器工作流

```
选择模板 → 创建容器 → 配置调整 → 安装游戏 → 启动运行
```

**详细步骤：**

1. 用户执行 `grapevine template list` 查看可用模板
2. 用户选择 gaming-dx11 模板
3. 用户执行 `grapevine create --name skyrim --template gaming-dx11`
4. 系统检查模板所需组件是否已安装（DXVK、Turnip 等）
5. 若组件缺失，系统提示安装并自动安装
6. 系统创建容器目录结构
7. 系统根据模板初始化 rootfs 和 Wine prefix
8. 系统生成 container.yml（含图形驱动=Turnip、DXVK=2.3、音频=PulseAudio）
9. 容器创建完成
10. 用户根据需要调整配置（如 `grapevine config set skyrim graphics.mangohud true`）
11. 用户将游戏文件复制到映射目录（如 /sdcard/Games/Skyrim）
12. 用户执行 `grapevine start skyrim`
13. 系统初始化图形子系统（Turnip + DXVK）
14. 系统初始化音频子系统（PulseAudio）
15. 系统挂载存储映射
16. 系统启动 Wine 实例
17. 容器运行中，用户可通过 Wine 运行游戏

**异常处理：**

- GPU 不支持 Turnip：自动回退到 VirGL，提示性能可能下降
- DXVK 安装失败：提示手动安装或切换到 Wine 内置 D3D
- 游戏文件格式不支持：提示支持的文件格式

---

### 6.3 运行 Windows 应用工作流

```
启动容器 → 运行应用 → 使用应用 → 关闭应用 → 停止容器
```

**详细步骤：**

1. 用户执行 `grapevine start <容器名称>`
2. 系统加载 container.yml 配置
3. 系统配置环境变量（Box86/Box64 库路径、Wine 路径、GPU 驱动路径）
4. 系统启动图形子系统
5. 系统启动音频子系统
6. 系统挂载存储映射
7. 系统启动 Wine 实例
8. 用户执行 `grapevine run <容器名称> --exe "C:\Program Files\App\app.exe"`
9. 系统在容器环境中启动应用进程
10. 应用通过 Box86/Box64 转译执行
11. 应用图形通过 DXVK/VKD3D → Vulkan → Turnip 渲染
12. 应用音频通过 Wine → PulseAudio → Android 音频输出
13. 用户正常使用应用
14. 用户关闭应用
15. 用户执行 `grapevine stop <容器名称>`
16. 系统优雅终止 Wine 进程
17. 系统释放资源

**异常处理：**

- 应用崩溃：系统捕获崩溃信号，记录崩溃日志，容器保持运行
- 图形渲染错误：自动回退到软件渲染，提示检查驱动配置
- 音频无输出：提示检查音频后端配置和 Android 音频权限
- 应用无响应：用户可强制终止应用进程而不停止容器

---

### 6.4 快照与回滚工作流

```
停止容器 → 创建快照 → 修改容器 → 验证变更 → 回滚（可选）→ 恢复运行
```

**详细步骤：**

1. 用户在安装重要软件或修改配置前，决定创建快照
2. 用户执行 `grapevine stop <容器名称>`
3. 用户执行 `grapevine snapshot create <容器名称> --name "before-update"`
4. 系统扫描容器文件系统
5. 系统计算增量差异（首个快照为全量）
6. 系统存储快照数据
7. 用户启动容器并进行变更（安装软件、修改配置等）
8. 变更后发现问题，决定回滚
9. 用户执行 `grapevine stop <容器名称>`
10. 用户执行 `grapevine snapshot list <容器名称>` 查看快照列表
11. 用户执行 `grapevine snapshot rollback <容器名称> --snapshot "before-update"`
12. 系统提示确认（回滚将丢失快照后的变更）
13. 用户确认
14. 系统根据快照链重建容器状态
15. 容器恢复到快照点状态
16. 用户执行 `grapevine start <容器名称>` 恢复使用

**异常处理：**

- 快照链损坏：提示从更早的快照回滚
- 磁盘空间不足无法创建快照：提示清理或删除旧快照
- 回滚过程中 I/O 错误：中止回滚，保持当前状态

---

### 6.5 容器导出与导入工作流

```
导出：停止容器 → 打包容器 → 传输文件
导入：接收文件 → 验证完整性 → 解压还原 → 注册容器
```

**详细步骤（导出）：**

1. 用户执行 `grapevine stop <容器名称>`
2. 用户执行 `grapevine export <容器名称> --output /sdcard/backup/my-container.gv.tar.gz`
3. 系统暂停容器（确保数据一致性）
4. 系统将容器目录打包为 tar.gz 归档
5. 系统生成 manifest.sha256 校验文件
6. 归档完成，用户可将文件传输到其他设备

**详细步骤（导入）：**

1. 用户将归档文件传输到目标设备
2. 用户执行 `grapevine import /sdcard/backup/my-container.gv.tar.gz --name my-container`
3. 系统校验归档完整性（SHA256）
4. 系统验证名称唯一性
5. 系统创建容器目录
6. 系统解压归档
7. 系统更新容器ID和名称
8. 系统注册容器到索引
9. 用户可启动导入的容器

**异常处理：**

- 归档文件损坏：校验失败，拒绝导入
- 名称冲突：提示使用其他名称或 --rename 参数
- 磁盘空间不足：提示所需空间
- 组件版本不匹配：提示安装对应版本组件

---

### 6.6 组件安装与更新工作流

```
检查更新 → 选择组件 → 下载安装 → 验证 → 切换版本
```

**详细步骤：**

1. 用户执行 `grapevine component update --check`
2. 系统查询远程仓库获取最新版本信息
3. 系统对比本地已安装版本
4. 系统输出可更新组件列表
5. 用户选择要更新的组件
6. 用户执行 `grapevine component install wine --version 9.5`
7. 系统下载组件发布包
8. 系统校验 SHA256
9. 系统解压到组件存储目录
10. 系统注册新版本
11. 用户执行 `grapevine component switch wine --version 9.5`
12. 系统更新活跃版本符号链接
13. 用户重启容器使用新版本

**异常处理：**

- 下载失败：重试 3 次，失败后提示网络问题
- 校验失败：删除已下载文件，提示文件损坏
- 新版本与容器不兼容：警告但不阻止，提示可能的问题

---

### 6.7 图形驱动切换工作流

```
识别问题 → 停止容器 → 切换驱动 → 重启容器 → 验证
```

**详细步骤：**

1. 用户发现游戏画面渲染异常或性能不佳
2. 用户执行 `grapevine stop <容器名称>`
3. 用户查看当前图形配置 `grapevine config get <容器名称> graphics`
4. 用户决定切换驱动（如从 VirGL 切换到 Turnip）
5. 用户执行 `grapevine config set <容器名称> graphics.driver turnip`
6. 系统验证 Turnip 驱动已安装且 GPU 兼容
7. 系统更新 container.yml
8. 系统更新 Wine prefix 中的 DLL 覆盖和注册表
9. 用户执行 `grapevine start <容器名称>`
10. 系统使用新驱动初始化图形子系统
11. 用户运行应用验证图形是否正常

**异常处理：**

- GPU 不兼容目标驱动：拒绝切换，推荐可用驱动
- 驱动未安装：提示先安装驱动组件
- 切换后渲染黑屏：自动回退到原驱动，记录错误日志

---

### 6.8 故障排查工作流

```
发现问题 → 运行诊断 → 分析日志 → 定位原因 → 修复 → 验证
```

**详细步骤：**

1. 用户遇到问题（应用崩溃、无声音、图形异常等）
2. 用户执行 `grapevine doctor`
3. 系统自动检查以下项目：
   - Termux 版本和权限
   - CPU 架构和 GPU 型号
   - 已安装组件及版本
   - 容器状态和配置
   - 存储空间和权限
   - 网络连接
4. 系统输出诊断报告（通过/警告/失败）
5. 对于失败项，系统给出修复建议
6. 用户根据建议执行修复操作
7. 若自动诊断无法解决，用户查看日志：
   - `grapevine log <容器名称>` 查看容器日志
   - Wine 日志：`~/.grapevine/containers/<名称>/prefix/drive_c/wine.log`
   - 系统日志：`~/.grapevine/grapevine.log`
8. 用户根据日志信息定位问题原因
9. 用户执行修复操作（切换驱动、更新组件、修改配置等）
10. 用户重新启动容器验证问题是否解决

**常见故障与解决方案：**

| 故障现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 应用启动后黑屏 | GPU 驱动不兼容 | 切换图形驱动 |
| 无声音 | 音频后端配置错误 | 切换 PulseAudio/ALSA |
| 应用崩溃 | Box86/Box64 版本不兼容 | 更新转译器版本 |
| 性能极低 | DXVK 未启用 | 检查 DLL 覆盖配置 |
| 键盘输入无响应 | Input Bridge 未启动 | 启动 Input Bridge 服务 |
| 文件无法访问 | 存储映射未配置 | 添加存储映射 |
| 网络应用无法连接 | 网络模式为 isolated | 切换到 host 模式 |
