## 2. 项目背景与问题陈述

### 2.1 项目背景

随着 ARM64 移动设备性能的不断提升，在 Android 平台上运行 Windows x86/x64 应用程序的需求日益增长。当前主流方案通过 Box86/Box64 指令转译与 Wine/Proton 兼容层实现这一目标，但在容器化管理、环境可复现性和运维效率方面存在显著不足。

### 2.2 现有方案痛点分析

#### 2.2.1 Winlator 的痛点

| 痛点编号 | 痛点描述 | 影响程度 |
|----------|----------|----------|
| P-W1 | 组件更新依赖 APK 发版，无法独立热更新 Wine/Box64/DXVK 等运行时组件 | 高 |
| P-W2 | 容器管理能力有限，仅支持基础的创建/删除/配置，缺乏快照、克隆、导入导出 | 高 |
| P-W3 | 所有容器共享同一 Wine 版本，无法为不同应用配置独立的兼容运行时 | 中 |
| P-W4 | 不支持 Proton 兼容层，限制了 DirectX 12 应用的兼容性 | 中 |
| P-W5 | 无声明式配置，容器配置无法版本控制或共享复现 | 中 |
| P-W6 | 仅提供 GUI 界面，不支持 CLI 和脚本化自动化操作 | 中 |

#### 2.2.2 Mobox 的痛点

| 痛点编号 | 痛点描述 | 影响程度 |
|----------|----------|----------|
| P-M1 | 无真正的容器隔离，本质上仅是 Wine prefix 切换器，应用间可能互相干扰 | 高 |
| P-M2 | 缺乏快照/回滚机制，Wine prefix 损坏后只能重建 | 高 |
| P-M3 | 无模板系统，每次创建新环境需重复手动配置 | 中 |
| P-M4 | 菜单式 TUI 交互有限，不支持 CLI 自动化和脚本集成 | 中 |
| P-M5 | 无容器导入/导出功能，环境迁移困难 | 中 |
| P-M6 | 组件版本管理粗放，缺乏独立安装/更新/卸载的精细控制 | 低 |

#### 2.2.3 共性痛点

| 痛点编号 | 痛点描述 | 影响程度 |
|----------|----------|----------|
| P-C1 | 环境不可复现：无法保证同一配置在不同设备上产生一致的运行环境 | 高 |
| P-C2 | 故障恢复困难：配置错误或注册表损坏后缺乏回滚手段 | 高 |
| P-C3 | 环境迁移困难：无法将调试好的容器环境打包分享给其他用户 | 中 |
| P-C4 | 图形驱动选择缺乏智能性：用户需手动判断和选择最优驱动 | 中 |

### 2.3 问题陈述

如何在无需 root 权限的 ARM64 Android 设备上，通过 Termux 提供一个专业级的 Windows 兼容容器管理平台，实现：

1. **完整的容器生命周期管理**：创建、启动、停止、删除、克隆、快照、回滚、导入、导出
2. **环境可复现性**：通过声明式配置和模板系统，确保容器环境可版本控制、可共享、可复现
3. **运行时灵活性**：每个容器可独立配置 Wine/Proton 版本、图形驱动、音频后端等运行时参数
4. **自动化支持**：提供完整的 CLI 命令行接口，支持脚本化操作和第三方工具集成

## 4. 功能性需求

### 4.1 容器管理模块

#### FR-CM-001：创建容器

| 项目 | 内容 |
|------|------|
| 需求ID | FR-CM-001 |
| 名称 | 创建容器 |
| 描述 | 用户可通过指定名称和可选模板创建新的 Grapevine 容器。创建过程包括初始化容器目录结构、生成默认 container.yml 配置文件、创建 PRoot 隔离的 rootfs 文件系统视图、初始化 Wine prefix。 |
| 优先级 | P0 |
| 验收标准 | 1. 执行 `grapevine create <name>` 成功创建容器，返回创建成功提示；2. 容器目录 `~/.grapevine/containers/<name>/` 包含 container.yml、rootfs/、prefix/、snapshots/、logs/ 目录和 state.json 文件；3. 重复创建同名容器返回错误提示；4. 容器名称仅允许小写字母、数字和连字符，长度 1-63 字符；5. 创建后容器状态为 `stopped` |

#### FR-CM-002：从模板创建容器

| 项目 | 内容 |
|------|------|
| 需求ID | FR-CM-002 |
| 名称 | 从模板创建容器 |
| 描述 | 用户可在创建容器时指定模板名称，系统根据模板预设的配置初始化容器，包括 Wine 版本、图形驱动、预装组件等。 |
| 优先级 | P0 |
| 验收标准 | 1. 执行 `grapevine create <name> --template <template>` 成功创建基于模板的容器；2. 容器的 container.yml 包含模板定义的配置项；3. 模板中指定的组件（DXVK、vcredist 等）已安装到 Wine prefix 中；4. 指定不存在的模板返回错误提示并列出可用模板 |

#### FR-CM-003：启动容器

| 项目 | 内容 |
|------|------|
| 需求ID | FR-CM-003 |
| 名称 | 启动容器 |
| 描述 | 用户可启动处于 stopped 状态的容器。启动过程包括配置 PRoot 隔离环境、设置 Box86/Box64 环境变量、初始化图形驱动、配置音频后端、挂载共享目录、启动 Wine 进程。 |
| 优先级 | P0 |
| 验收标准 | 1. 执行 `grapevine start <name>` 成功启动容器，容器状态变为 `running`；2. PRoot 隔离环境正确设置，容器内路径映射正确；3. Wine 进程在容器内正常运行；4. 启动已运行的容器返回提示信息而非错误；5. 启动处于 `error` 状态的容器返回警告并要求确认 |

#### FR-CM-004：停止容器

| 项目 | 内容 |
|------|------|
| 需求ID | FR-CM-004 |
| 名称 | 停止容器 |

| 优先级 | P0 |

#### FR-CM-005：删除容器

|------|------|

|------|------|

|------|------|

## 5. 非功能性需求

### 5.1 性能需求

| 需求ID | 名称 | 描述 | 验收标准 |
|--------|------|------|----------|
| NFR-PF-001 | 容器启动时间 | 容器从 stopped 到 running 的启动时间应在合理范围内 | 首次启动（含 Wine prefix 初始化）≤ 60 秒；后续启动 ≤ 15 秒（不含组件下载时间） |
| NFR-PF-002 | 快照创建时间 | 快照创建操作应在合理时间内完成 | 增量快照创建 ≤ 30 秒（1GB prefix）；首次快照创建 ≤ 120 秒（1GB prefix） |
| NFR-PF-003 | CLI 响应时间 | CLI 命令响应应在合理范围内 | 纯查询命令（list/info）≤ 2 秒；状态变更命令（start/stop）≤ 5 秒返回操作结果 |
| NFR-PF-004 | 存储效率 | 增量快照和容器克隆应有效节省存储空间 | 增量快照相比全量快照节省 ≥ 50% 存储空间（典型使用场景） |
| NFR-PF-005 | 图形渲染帧率 | 在推荐配置下，图形渲染应达到可用的帧率 | DX9/DX11 应用在 Turnip 驱动下 ≥ 15 FPS（1280x720 分辨率，中端 Adreno 660+ 设备） |

### 5.2 安全性需求

| 需求ID | 名称 | 描述 | 验收标准 |
|--------|------|------|----------|
| NFR-SC-001 | 容器隔离 | 容器间文件系统应互相隔离 | 容器 A 无法访问容器 B 的 rootfs 和 prefix 内容 |
| NFR-SC-002 | 网络隔离 | isolated 模式下容器应无法访问外部网络 | isolated 模式下所有出站网络连接被阻止 |
| NFR-SC-003 | 只读挂载 | 只读共享目录应正确阻止写入 | readonly=true 的共享目录在容器内写入操作返回权限错误 |
| NFR-SC-004 | 无 Root 运行 | 核心功能应在无 root 权限下正常运行 | 除 OOM 调优和资源限制外，所有功能无需 root 权限 |
| NFR-SC-005 | 敏感信息保护 | 配置文件和日志中不应明文存储敏感信息 | 日志中不记录环境变量中的密钥类值；配置导出时可选排除敏感配置 |

### 5.3 可靠性需求

| 需求ID | 名称 | 描述 | 验收标准 |
|--------|------|------|----------|
| NFR-RL-001 | 容器崩溃恢复 | 容器因错误退出后应能正确恢复到 error 状态 | 错误退出后容器状态为 error，日志记录错误原因，可通过 restart 恢复 |
| NFR-RL-002 | 快照完整性 | 快照数据应保证完整性 | 快照创建后可通过校验和验证数据完整性；回滚操作后 prefix 状态与快照一致 |
| NFR-RL-003 | 原子操作 | 关键操作应具有原子性 | 容器创建、删除、快照回滚等操作要么完全成功，要么完全回滚，不留中间状态 |
| NFR-RL-004 | 进程清理 | 容器停止后应正确清理所有子进程 | stop 后无残留 Wine/Box64 子进程；force stop 确保所有子进程被 SIGKILL |

## 6. 约束与假设

### 6.1 约束

| 编号 | 约束描述 |

## 10. 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| 容器 | Container | Grapevine 中的基本管理单元，包含独立的文件系统视图、Wine prefix、配置文件和运行时状态，通过 PRoot 实现隔离 |
| Wine Prefix | Wine Prefix | Wine 创建的虚拟 Windows 环境目录，包含 drive_c、注册表、设备映射等，模拟完整的 Windows 文件系统 |
| PRoot | PRoot | 用户空间虚拟化工具，通过 ptrace 系统调用拦截实现文件系统路径重映射，无需 root 权限 |
| Box86 | Box86 | x86（32位）到 ARM32/ARM64 的动态二进制翻译器，将 x86 指令实时翻译为 ARM 指令执行 |
| Box64 | Box64 | x64（64位）到 ARM64 的动态二进制翻译器，将 x86-64 指令实时翻译为 ARM64 指令执行 |
| Wine | Wine | Windows API 兼容层，将 Windows 系统调用翻译为 POSIX 调用，使 Windows 应用可在 Linux 上运行 |
| Proton | Proton | Valve 基于 Wine 开发的增强版兼容层，集成多种游戏兼容性补丁，主要用于 Steam 游戏支持 |
| DXVK | DXVK | DirectX 9/10/11 到 Vulkan 的翻译层，将 DirectX 图形调用转换为 Vulkan 调用 |
| VKD3D | VKD3D | DirectX 12 到 Vulkan 的翻译层，将 DX12 图形调用转换为 Vulkan 调用 |
| D8VK | D8VK | DirectX 8 到 Vulkan 的翻译层，将 DX8 图形调用转换为 Vulkan 调用，用于老旧游戏 |
| WineD3D | WineD3D | Wine 内置的 DirectX 到 OpenGL 翻译层，作为 DXVK 不可用时的回退路径 |
| Turnip | Turnip | Mesa 项目中的 Adreno GPU Vulkan 开源驱动，为高通 Adreno GPU 提供原生 Vulkan 支持 |
| VirGL | VirGL | 通过 OpenGL ES 模拟 Vulkan 的虚拟 GPU 驱动，兼容性最广但性能较低 |
| Zink | Zink | Mesa 中的 Vulkan 到 OpenGL 转译层，在仅有 OpenGL 支持的 GPU 上提供 Vulkan API |
| Dynarec | Dynamic Recompiler | 动态二进制翻译器，Box86/Box64 的核心组件，将 x86/x64 指令块即时编译为 ARM 指令并缓存 |
| Termux | Termux | Android 终端模拟器和 Linux 环境应用，提供包管理和命令行环境 |
| Termux-X11 | Termux-X11 | Termux 的 X11 显示服务插件，为图形应用提供 X Window System 显示支持 |
| glibc | GNU C Library | GNU 标准 C 库，Wine 和许多 Linux 程序的运行时依赖，与 Android 的 Bionic libc 不同 |
| Bionic | Bionic libc | Android 原生 C 库，Termux 默认使用，与 glibc 存在接口差异 |
| 快照 | Snapshot | 容器在某一时刻的完整状态保存，包括 Wine prefix、注册表和配置文件，支持增量存储 |
| 回滚 | Rollback | 将容器恢复到指定快照时的状态，撤销快照后的所有变更 |
| 模板 | Template | 预配置的容器蓝图，包含 Wine 版本、图形驱动、预装组件等预设，用于快速创建特定用途的容器 |
| 声明式配置 | Declarative Configuration | 通过 YAML 文件描述容器的期望状态（而非操作步骤），系统负责将当前状态收敛到期望状态 |
| 绑定挂载 | Bind Mount | 将主机上的目录挂载到容器的指定路径，使容器可访问主机文件 |
| OOM | Out-Of-Memory | 内存不足，Android 系统的 OOM Killer 可能杀死占用内存较多的后台进程（如 Termux） |
| 存储卷 | Volume | 独立于容器的共享存储空间，可挂载到多个容器实现文件共享 |
| DLL 覆盖 | DLL Override | Wine 的 DLL 加载顺序配置，控制使用 Windows 原生 DLL 还是 Wine 内置实现 |
| 注册表补丁 | Registry Patch | 对 Wine prefix 注册表的声明式修改，用于调整 Windows 应用行为 |
| 组件 | Component | Grapevine 管理的运行时软件包，如 Wine、Box64、DXVK 等，支持版本化管理 |
| TUI | Terminal User Interface | 终端用户界面，在命令行终端中提供的交互式图形界面 |
| CLI | Command Line Interface | 命令行界面，通过文本命令与系统交互 |
| rootfs | Root Filesystem | 容器的根文件系统目录树，由 PRoot 隔离，包含系统库和配置文件 |
